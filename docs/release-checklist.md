# リリース前の実機チェックリスト

自動テストでは確かめられない項目（[仕様一覧](spec/README.md)で種類に「手動」がある項目）を、リリースのたびに実機で確かめるための手順です。各手順の末尾に、対応する仕様の ID を書いています。種類に「手動」がある項目がすべてここに載っていることは、`scripts/check-spec-coverage.mjs` が確かめます。

- 所要時間の目安: 全部で約 35 分（準備を含む）。本物のサービスでの会議の自動検出（A-4）が 10 分で、いちばん長い。ほかに、長い録音の確認（A-5）で約 65 分待つ（操作は 3 分。待つ間は、録音を使わない作業をしてよい）。
- 結果は、手順ごとに「OK／NG（起きたこと）」を残します。NG が 1 つでもあれば、リリースを止めます。
- 手順のうち、あとで自動テストに置き換えられるものには「自動化の候補」と書いています。置き換えたら、仕様一覧の種類から「手動」を外し、この一覧からも消します。
- プロキシを通さないと外部に出られない環境での動作は、この一覧の対象外です（仕様一覧の「エラーの扱い」に、未検証の項目として書いています）。

## 準備（10 分）

- Windows 10 または 11 の PC。Kiroscribe を入れたことがない Windows のユーザー（新しく作る）を用意する。
- ヘッドホンとマイク（PC の内蔵でよい）。
- 通話の相手（2 台目の PC か、スマートフォン）。Google Meet と、今回確かめるもう 1 つのサービスのアカウント。
- テスト用の OpenAI・Anthropic の API キー（料金がかかる。全体で数十円ほど）。
- 確かめるインストーラ。公開の前は、CI（main ブランチ）が保存したインストーラを使う。

## A. 公開の前に確かめること

### A-1. インストール（5 分）

1. 新しい Windows のユーザーで、インストーラ `Kiroscribe_<バージョン>_x64-setup.exe` を実行する。
2. 「Windows によって PC が保護されました」と出たら、「詳細情報」→「実行」を選ぶ。
3. 管理者のパスワードを求められずに、最後まで進むことを確かめる。インストーラの表示が日本語であることを確かめる。
4. インストールが終わったら Kiroscribe を起動し、メインウィンドウが出ることを確かめる。設定の「このアプリについて」のバージョンが、リリースするバージョンであることを確かめる。

古い版の上に入れたとき・アプリ内で更新したときにデータが残ること、アンインストールは、CI のインストールと更新のテスト（installer-e2e）が、本物のインストーラで確かめています。

対応: REL-001、REL-002

### A-2. 本物の文字起こし（3 分）

本物の音声デバイスでの取り込み（マイクの一覧・自分と相手・入力のバー・一時停止・マイクの異常）は、CI の「本物の音声デバイス」のジョブが、仮想のオーディオケーブルで確かめています。ここでは、本物の OpenAI の API で文字になることだけを確かめます。

1. 新しいノートを作り、ヘッドホンをして「録音を開始」を押す。マイクに向かって 2〜3 文を話し、PC で人が話している動画を少し再生する。
2. 数秒後に、話した内容が「自分」、動画の内容が「相手」として、正しい日本語で表示されることを確かめる。
3. 「停止」を押し、最後に話した内容まで表示されることを確かめる。

対応: TRN-022

### A-3. 議事録と AI チャット（5 分）

1. A-2 で録音したノートに、メモを 2〜3 行書く。「議事録を作成」を押す。議事録が少しずつ表示され、終わるとタイトルが付く（空だった場合）ことを確かめる。メモに書いた行が濃く表示されることを確かめる。
2. 「AI チャット」を開き、「この会議で決まったことは？」を押す。回答が少しずつ表示され、内容が録音した会話に沿っていることを確かめる。
3. 設定で Claude のモデルを別のものに変えて保存し、もう一度質問して、回答が返ることを確かめる（選択メニューの 4 つのモデルのうち、既定と、もう 1 つ）。

対応: MIN-020、CHT-013

### A-4. 本物のサービスでの会議の自動検出（10 分）

検出の仕組み（判定表の印から開始・終了を決め、録音を始め・止めること）と、ポップアップの表示・ドラッグは、CI が確かめています（会議の窓・ボタンを出すプログラムと Edge のページで再現する）。ここでは、本物のサービスが、いまも判定表の印（退出のボタン・会議の窓・タブの題など）を出すことを確かめます。サービスは、リリースのたびに 2 つ選びます（Google Meet と、Slack ハドル・Zoom・Teams・Discord から 1 つを順番に）。サービスごとの操作と、期待する判定は、[会議の検出の実機の確認](meeting-detection-check.md)にあります。メインウィンドウは閉じて（トレイに残して）おきます。

1. 相手と会議・通話に入る。数秒（2〜6 秒）後に、画面の右下にポップアップが出て、サービスの名前と「自動で録音・文字起こしを始めました」が表示されることを確かめる。ポップアップが出ても、会議のウィンドウの入力（フォーカス）が奪われないことを確かめる（1 つのサービスでは、Windows の「拡大/縮小」を 125% か 150% にして、ポップアップがタスクバーにかからないことも確かめる）。
2. 「ノートを開く」を押し、自分と相手の文字起こしが増えていくことを確かめる。ミュートにして 1 分黙っていても、録音が止まらないことを確かめる。
3. 会議・通話を抜ける。約 20 秒後（Google Meet で退出後の画面が出たときは、すぐ）に「録音を停止しました」に変わることを確かめる。
4. Discord を選んだ回は、Discord を起動してから 10 分以上たってから通話に入り、数秒で録音が始まることを確かめる（MTG-030）。
5. 検出しなかった・止まらなかったときは、設定の「このアプリについて」の「詳しい記録を残す（24 時間）」をオンにしてやり直し、「デバッグ用のログを保存…」で zip を保存する。zip のログ（`logs/`）の `meeting.check` の行で、サービスごとの判定と立っている印（`services`）を確かめ、`meeting-detection.json` を回帰テストに加えて（`crates/core/tests/fixtures/meetings/README.md`）、判定表を直してから、リリースする。

### A-5. 長い録音の確認（操作 3 分、待ち時間 約 65 分）

録音が 1 時間を超えたときの確かめ方（確認を出す条件、「止める」「続ける」、答えがないときの停止）は、CI の結合テストが時刻を進めて確かめています。ここでは、実際の時間の流れで確認が出ることと、Windows の通知が出ることを確かめます。A-1〜A-4 が終わってから始めます。

1. 新しいノートを作り、「録音を開始」を押す。マイクをミュートにし、PC で音を鳴らさないでおく。メインウィンドウは閉じて（トレイに残して）おく。
2. 約 60 分後に、画面の右下のポップアップに「会議は終わりましたか？」と、止めるまでの残り時間が出ることを確かめる。答えずに待つ。
3. 2 分後に、ポップアップが「答えがなかったため、録音を停止しました。「<ノートのタイトル>」に保存しています。」に変わり、同じ文の Windows の通知が出ることを確かめる。トレイのメニューの「録音を停止」が選べなくなっていることを確かめる。

対応: REC-026

### A-6. デバッグ用のログの提出（3 分）

ログを zip にまとめる処理と、入口との受け渡し（ヘッダー・応答・断られたときの文）は、CI の単体・結合テストが確かめています。ここでは、本物の入口に届くことを確かめます。

1. 設定の「このアプリについて」の「デバッグ用のログを提出…」を押し、確認の文を読んで OK を押す。
2. 進み具合のあとに「ログを提出しました。提出の番号: <番号>」が出ることを確かめる。
3. 入口の README の手順で、その番号の zip を取り出せ、展開するとログが入っていることを確かめる。

対応: SET-020

## 公開の直後

公開の直後の確認は、リリースのワークフローが行います（利用者のアプリが見る latest.json が新しいバージョンを指し、そこから取得したインストーラが、ビルドしたものと同じで、署名をアプリの公開鍵と 1 つ前のリリースの公開鍵で検証できること。ビルドの来歴の証明も確かめます）。確かめられなければ、ワークフローがリリースをプレリリースに戻して、利用者のアプリに配られないようにします。

アプリ内の更新（ボタンを押した場合と自動の場合、署名の合わない更新を入れないこと）・古い版の上へのインストール・アンインストールは、CI のインストールと更新のテスト（installer-e2e）が、本物のインストーラで確かめています。リリースのワークフローは、このテストが通らなければ公開しません。
