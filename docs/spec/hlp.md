# HLP: ヘルプ

アプリの中で見られる「使い方」と「リリースノート」。

- **HLP-001** ［単体］ サイドバーの「？」を押すとヘルプが「使い方」のタブで開く。設定画面の「使い方」「リリースノート」を押すと、そのタブで開く。
- **HLP-002** ［単体］ ヘルプでは「使い方」と「リリースノート」のタブを切り替えられる。内容は、それぞれのタブを最初に開いたときに取得し、取得の間は「読み込んでいます…」と表示する。
- **HLP-003** ［結合］ 「使い方」は、公開リポジトリの `docs/guide.md`（main ブランチ）を GitHub から取得して表示する。取得は 10 秒で打ち切る。
- **HLP-004** ［結合］ 「リリースノート」は、GitHub の公開済みのリリース（新しいものから 20 件まで）を取得して、新しい順に表示する。下書きとプレリリースは表示しない。
- **HLP-005** ［単体・結合］ GitHub から取得できなかったとき（オフライン、HTTP のエラー、内容が空、形式が違う、リリースが 1 つもない）は、エラーにせず、同じバージョンのアプリで前に取得して保存した内容を表示する。保存した内容もなければ、アプリに同梱の内容（使い方と変更履歴）を表示する。取得できた内容は、次のために保存する（失敗は保存しない）。
- **HLP-006** ［単体］ 別のバージョンのアプリで保存した内容と、壊れている保存内容は使わない（アプリを更新した直後は、同梱の内容のほうが新しいため）。
- **HLP-007** ［単体］ 最新の内容を取得できなかったときは、どの内容を表示しているかを知らせる。保存した内容なら「オンラインの最新版を取得できないため、保存済みの内容を表示しています（<月>/<日> <時>:<分> に取得）」、同梱の内容なら「…アプリに同梱の内容を表示しています」。「再読み込み」を押すと取得し直す。取得できているときは何も出さない。
- **HLP-008** ［単体］ リリースノートは、リリースごとに、名前（なければタグ名）、公開日（「2026年11月21日」の形）、本文（空なら「説明はありません」）を表示する。いまのアプリと同じバージョンのリリースには「現在のバージョン」と表示する。リリースが 1 つもなければ「リリースノートはまだありません」と表示する。
- **HLP-009** ［単体］ 同梱の変更履歴（CHANGELOG.md）は、「## バージョン (日付)」の見出しごとに 1 つのリリースとして表示する。「## v0.2.1（日付）」「## [0.2.0] - 日付」の書き方も読める。バージョンでない見出しの節と、最初の節より前の文は表示しない。コードブロックの中の「## 」は見出しとして扱わない。
- **HLP-010** ［単体］ 同梱の変更履歴のいちばん上の節は、そのアプリのバージョンの節で、本文がある（リリースの前に検査する）。
- **HLP-011** ［単体］ ヘルプの中の `https://` のリンクと、各リリースの「GitHub」のリンクは、押す（または Enter）と既定のブラウザで開く。アプリの画面は別のページに移らない。`https://` 以外のリンクは押せない文字として表示し、画像は表示しない。
- **HLP-012** ［単体］ リンクを開けなかったときは、ヘルプの中に理由を表示する。
- **HLP-013** ［単体］ ヘルプは、Esc、画面の外側のクリック、× で閉じる。
- **HLP-014** ［結合］ GitHub への問い合わせには、アプリの名前とバージョン（「Kiroscribe/<バージョン>」）を付ける。ノート・音声・API キーは送らない。
- **HLP-015** ［結合］ 製品の取得元（本物の GitHub）から、いまも使い方とリリースノートを取得して読める（使い方は同梱のものと同じ文書で、リリースノートは公開済みのリリースが新しい順に並び、各リリースの「GitHub」のリンクは、アプリが既定のブラウザで開いてよい、このリポジトリのリリースのページを指す）。CI で、インターネットにつないで確かめる。
