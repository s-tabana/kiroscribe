# ERR: エラーの扱い

失敗したときの知らせ方と、再試行。機能ごとのエラーは、それぞれの節にも書いてある。

- **ERR-001** ［単体］ 操作に失敗したときは、理由を日本語の文で画面の上部に表示する。知らせは × で閉じられる。
- **ERR-002** ［単体］ 知らせの文に「API キー」が含まれるときは、「設定を開く」ボタンを付ける。押すと設定画面が開き、知らせは消える。
- **ERR-003** ［単体・結合］ OpenAI・Anthropic がエラーを返したときの文は、HTTP 401・403 なら「<サービス> の API キーが正しくないか、権限がありません（HTTP <番号>: <詳細>）。設定画面でキーを確認してください」、429 なら「<サービス> の利用上限に達しました。しばらく待ってから試してください（HTTP 429: <詳細>）」、それ以外は「<サービス> がエラーを返しました（HTTP <番号>）: <詳細>」。
- **ERR-004** ［単体］ エラーの詳細には、応答の中のメッセージ（`error.message`）を使う。なければ応答の本文の先頭 300 文字、本文が空なら「（本文なし）」とする。
- **ERR-005** ［結合］ 通信そのものに失敗したときの文は、時間切れなら「応答がなくタイムアウトしました」、接続できないなら「接続できませんでした。インターネット接続やプロキシの設定を確認してください」、それ以外は「通信に失敗しました」（いずれも原因を添える）。
- **ERR-006** ［単体］ 再試行するのは、通信の失敗と HTTP 408・429・500 番台だけ。キーの誤り（401）や送った内容の誤り（400）などは再試行しない。待つ時間は 1 秒・2 秒・4 秒・8 秒と伸び、8 秒が上限。試すのは最初の 1 回を含めて最大 4 回。
- **ERR-007** ［結合］ Claude の応答の途中で届くエラーは、過負荷なら HTTP 529、利用上限なら 429、サーバーの問題なら 500、それ以外は 400 と同じに扱う（ERR-003・ERR-006 に従う）。
- **ERR-008** ［単体］ Claude からの応答は、通信の区切りがどこで分かれても（日本語の 1 文字の途中でも）、文字が壊れずに表示される。
- **ERR-009** ［単体］ 利用者が中止した場合（「中止しました」）は、エラーの知らせを出さない。
- **ERR-010** ［単体］ 録音中に起きた問題（文字起こしの失敗、デバイスの問題など）は、どのノートを開いていても、画面の上部の知らせに表示する。
- **ERR-011** ［単体］ ノートを開けなかったときは、ノートの場所に理由を表示する。理由の分からない失敗は「不明なエラーが発生しました」と表示する。
- **ERR-012** ［未検証］ 外部との通信は、OS や環境変数のプロキシの設定に従う。プロキシのある環境での動作は、自動テストでもリリース前の実機チェックリストでも確かめていない。
