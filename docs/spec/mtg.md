# MTG: 会議の自動検出

会議に参加したことを検出して自動で録音し、抜けたら止める（Windows）。
検出は、サービスごとの判定表（[判定表](#判定表)）で行う。

## 判定表

判定表は、サービス（Google Meet・Slack ハドル・Discord・Teams・Zoom）ごとに、会議に参加中であることを示す印を並べた表。
製品に組み込み（`crates/core/src/meeting_rules.toml`）、利用者は変えられない。
2 秒ごとに PC の様子を調べ、印が立っているかを当てはめて、会議の開始と終了を決める（MTG-007〜MTG-010）。

### 印の強さ

| 強さ | 意味 | 例 |
| --- | --- | --- |
| 強（strong） | 1 つで開始する。会議に参加中にしか出ないもの | 退出・切断のボタン、Zoom の会議の窓 |
| 中（medium） | 中・弱と合わせて 2 つで開始する | 会議のタブの題、ハドルの窓 |
| 弱（weak） | 中・弱と合わせて 2 つで開始する | マイクの使用、再生の音 |
| 打ち消し（veto） | その文脈では始めない。会議の文脈に出たら、すぐに終える | 待機画面の参加ボタン、Meet の退出後の画面 |

「開始のあとだけ」（`after_start`）の印は、会議が始まったあとの継続の判定にだけ数え、開始には数えない（MTG-009）。

### 印の種類

| 種類 | 見るもの | 立つ条件 |
| --- | --- | --- |
| 窓（window） | 対象のアプリのトップレベルの窓の題とクラス名 | 見えている窓（最小化を含む）で、題（`title`）かクラス名（`class`）が当たる |
| 部品（control） | 窓の中の部品（UI Automation の要素）の名前と種類 | 種類（`types`。既定は Button）が当たり、名前（`names`）が当たり、除外の名前（`exclude`）に当たらない。`title` を書いた印は、その題の窓の中だけ |
| 録音・再生（session） | オーディオのセッション（MTG-020） | 録音（`flow = "capture"`）は状態が Active。再生（`flow = "render"`、`audible = true`）は状態が Active で、音の大きさが `audible_peak`（0.01）以上 |

`apps` は対象のアプリの実行ファイルの名前（小文字）で、`browser` は対象のブラウザ（MTG-002）すべてを指す。

### 文脈

印は、同じ文脈の中だけで組み合わせる（MTG-004）。

| 文脈 | 入る印 |
| --- | --- |
| 窓 1 つ（ブラウザでは、その窓に表示中のタブ） | その窓の窓の印と部品の印、その窓のアプリの録音・再生の印 |
| デスクトップの会議アプリ 1 つ | そのアプリの録音・再生の印だけ |

- ブラウザの録音・再生の印は、そのサービスの窓か部品の印が立っている窓の文脈でだけ数える。
- 打ち消しの印は、その印のある窓の文脈だけに効く。デスクトップの会議アプリの文脈には、そのアプリのどれかの窓の打ち消しの印が効く。

### 名前と題の比べ方

窓の題・部品の名前・判定表の語は、小文字にし、ダッシュ（— – ― ‐ −）を「-」にそろえて比べる（MTG-028）。

| 書き方 | 当たる条件 |
| --- | --- |
| `語` | その語を含む |
| `^語` | その語で始まる。前に付いた未読の印（「(3) 」「• 」）は除いて比べる |
| `語$` | その語で終わる。窓の題では、最後の区切り（「 - 」「 — 」「 – 」）より後ろ（ブラウザの名前）を除いても比べる |
| `語 + 語` | どの語も含む |
| `@名前` | 判定表の `[words]` に書いた語の並びのどれか |

### 全体の値

| 値 | 内容 | 既定の表の値 |
| --- | --- | --- |
| `end_after_seconds` | 強い印も組み合わせもない状態がこれだけ続いたら終了 | 20 秒 |
| `combination_seconds` | 組み合わせで始めるときに、続いている必要がある時間 | 4 秒 |
| `combination_scans` | 組み合わせで始めるときに、その間に窓の中の部品を調べた回数 | 2 回 |
| `audible_peak` | 再生の音が鳴っているとみなす音の大きさ（ピーク） | 0.01 |

## 項目

- **MTG-001** ［単体］ 会議の検出は、組み込みの判定表（「判定表」の節）で行う。判定表の印は、対象のアプリ（判定表の `apps` に書いた実行ファイルと、対象のブラウザ）の窓・窓の中の部品・オーディオのセッションだけを見る。実行ファイルの名前は、大文字小文字を区別しない。
- **MTG-002** ［単体］ 対象のブラウザは、Chromium 系の chrome.exe・msedge.exe・brave.exe・vivaldi.exe・opera.exe・opera_gx.exe・arc.exe・thorium.exe・chromium.exe・supermium.exe・browser.exe（Yandex Browser）・whale.exe・comet.exe・dia.exe・atlas.exe・sidekick.exe・island.exe・duckduckgo.exe と、Firefox 系の firefox.exe・zen.exe・floorp.exe・librewolf.exe・waterfox.exe・mullvadbrowser.exe。設定で足したブラウザ（SET-021）も、この一覧のブラウザと同じに扱う。ただし、判定表に実行ファイルの名前を書いたデスクトップの会議アプリ（slack.exe・zoom.exe など）は、設定で足してもブラウザとして扱わず、その会議アプリとして判定する。一覧にも設定にもないアプリは、版情報や子プロセスからブラウザと推定しない。
- **MTG-003** ［単体］ 判定表にないアプリ（音声入力・録音のアプリ、Thunderbird など）のマイクの使用と再生の音は、会議の印にしない。ブラウザのマイクの使用と再生の音も、会議の窓か部品の印がない窓だけでは、会議の印にしない。会議アプリと一緒に入る更新・起動のためのプロセス（Slack の update.exe、Teams の ms-teamsupdate.exe・msteams_autostarter.exe）と、ほかのアプリも使う部品（msedgewebview2.exe、Zoom の SDK 用の zcscpthost.exe）も、対象にしない。これらは、設定で足すブラウザ（SET-021）に書いても対象にしない。
- **MTG-004** ［単体］ 印は、同じ文脈（窓 1 つ、ブラウザでは表示中のタブ。またはデスクトップの会議アプリ 1 つ）の中だけで組み合わせる。別の窓の退出ボタンで、待機画面の窓の会議を始めない。打ち消しの印は、その印のある窓の文脈だけに効く（Edge の待機画面の参加ボタンで、Zen で続いている会議を終えない）。
- **MTG-005** ［単体］ Kiroscribe 自身のオーディオのセッション（録音中）と窓は、判定に入れない。
- **MTG-006** ［単体］ 部品の印は、判定表の種類（既定は Button）の部品だけで立つ。名前に除外の語を含む部品では立たない（Slack の環境設定のチェックボックス「ハドルミーティングから自動的に退出する」や、名前に「自動的に」を含むボタンでは、参加中にしない）。
- **MTG-007** ［単体］ 強い印が 1 つ立っている文脈があれば、その回に会議の開始とする。強い印がなく、中・弱い印が合わせて 2 つ立っている文脈があるときは、その組み合わせが 4 秒続き、その間に窓の中の部品を 2 回以上調べたら、開始とする（待機画面を開いた直後や、タブを閉じる途中に、部品をまだ読めないまま始めない）。窓の印と部品の印（窓の題とタブの名前）は、同じ題から立つので、合わせて 1 つと数える。UI Automation を使えなかった回と、その文脈の窓の中を調べられなかった回は、調べた回に数えない（デスクトップの会議アプリの文脈では、そのアプリの窓のどれかの中を調べられた回だけを数える）。打ち消しの印のある文脈では始めない。途中で組み合わせが崩れたら数え直す。開始は 1 つの会議につき 1 回だけ。
- **MTG-008** ［単体］ 強い印も中・弱い印の組み合わせもない状態が 20 秒続いたら、会議の終了とする。20 秒以内に戻れば、続いているものとして扱う。会議の文脈（直前に強い印か組み合わせが立っていた文脈）に打ち消しの印が出たら、すぐに終了とする（Meet の「ミーティングから退出しました」の画面など）。退出したあともタブの題が残るだけでは、続いているとみなさない。
- **MTG-009** ［単体］ 会議が始まったあとは、「開始のあとだけ」の印も組み合わせに数える。ブラウザの会議は、会議のタブを背面にしても、そのタブがその窓のタブの一覧にあり、そのブラウザがマイクを使うか再生の音を鳴らしている間は、続いているとみなす。
- **MTG-010** ［単体・結合］ 会議が続いている間に別のサービスの会議が始まっても、新しい会議の開始は知らせない（判定は続け、ログには「ほかの会議」として書く）。続いていた会議が終わったとき、または強い印も組み合わせもなくなって終了の猶予に入ったときに、別のサービスの会議が続いていれば、前の会議の終了を知らせてから、その会議の開始を知らせ、新しいノートで録音を始める。前の録音の文字起こしの仕上げが終わってから、次の録音を始める（仕上げ中でも、次の会議の録音を取りこぼさない）。同じサービスの印がまた立ったときは、前の会議の続きとして扱う。
- **MTG-011** ［単体・結合・E2E］ 会議の開始を検出し、設定の「会議の自動検出」がオンで、録音していなければ、ノートを「<会議の名前> <月>/<日> <時>:<分>」（例「Google Meet 11/20 15:04」）のタイトルで作り、録音と文字起こしを始め、ポップアップで知らせる。作ったノートは、メインウィンドウの一覧の先頭にすぐ加わる。
- **MTG-012** ［結合・E2E］ 設定の「会議の自動検出」がオフのときは、会議を検出しても何もしない（ノートを作らず、ポップアップも出さない）。
- **MTG-013** ［結合］ すでに録音中（手動の録音を含む。仕上げ中も含む）に会議の開始を検出したときは、何もせず、いまの録音を続ける。
- **MTG-014** ［単体・結合］ 会議の開始を検出したとき OpenAI の API キーが未設定なら、ノートを作らず、ポップアップで「OpenAI の API キーが設定されていないため、自動で録音できませんでした」と知らせる。
- **MTG-015** ［結合］ ノートを作ったあとで録音を始められなかったとき（マイクがない、など）は、ポップアップで理由を知らせ、作った空のノートは消す（メインウィンドウの一覧にも加えない）。
- **MTG-016** ［単体・結合・E2E］ 会議の終了を検出したとき、自動で始めた録音が続いていれば、ポップアップに「仕上げ中」を表示して録音を止め、残りの文字起こしが終わったらポップアップに「停止」を表示する。
- **MTG-017** ［結合］ 手動で始めた録音は、会議が終わっても止めない。自動で始めた録音を利用者が先に止めていた場合、会議が終わっても何もしない。
- **MTG-018** ［結合］ 会議の途中で設定の「会議の自動検出」をオフにしても、自動で始めて続いている録音は、会議の終了で止まる。
- **MTG-019** ［結合］ 設定の「会議の自動検出」をオフからオンにした時点（設定画面での保存、またはトレイのメニュー）で会議中なら、その会議の録音を始める。自動で始めた録音を利用者が止めたあと、または手動の録音を止めたあとは、同じ会議が続いていても録音を始め直さない（録音を始めるのは、会議の開始を検出したときと、オフからオンに変えたときだけ）。
- **MTG-020** ［単体・結合］ オーディオのセッションは、Windows のすべての有効な録音・再生のデバイスについて、アプリごとに読む。録音の印は、状態が Active のセッションで立つ。再生の音の印は、状態が Active で、音の大きさ（IAudioMeterInformation のピーク。約 0.3 秒の間に 10 回読んだ最大）が 0.01 以上のセッションで立つ。セッションのアプリは実行ファイルの名前で照らし、名前を読めないときは、パッケージファミリー名が Slack（91750D7E.Slack_・com.tinyspeck.slackdesktop_）か Teams（MSTeams_・MicrosoftTeams_）で始まれば、そのアプリとする。Windows が記録しているマイクの使用状況（ConsentStore）は使わない。セッションの一覧を読めないときは、録音・再生の印が立たないものとして、ほかの印で判定を続ける。
- **MTG-021** ［単体］ Windows 以外では、会議を検出しない。
- **MTG-022** ［E2E］ E2E テスト用のビルド（cargo の feature `e2e`）では、実際の検出の代わりに、作業フォルダの `meeting.txt` に書いた会議アプリ（googleMeet・slackHuddle・zoom・teams・discord）の会議中として扱う（ファイルがない・空なら会議中ではない）。配布するビルドには、この差し替えは入らない（SEC-012）。
- **MTG-023** ［手動］ 実際の Google Meet・Slack ハドル・Zoom・Teams・Discord で、会議に入ると数秒後に自動で録音が始まり、抜けると約 20 秒後（Meet の退出後の画面が出たときは、すぐ）に止まる。ミュートのまま参加して黙っていても、録音は止まらない（リリースのたびに、Google Meet と、ほかの 1 つを順番に確かめる。手順は [会議の検出の実機の確認](../meeting-detection-check.md)）。
- **MTG-024** ［E2E］ 会議の検出は、製品と同じ仕組みで動く: Zoom の会議の窓のクラス（ZPContentViewWndClass）の窓を出してマイクを使うプログラム（Zoom.exe の名前）、「Disconnect」のボタンのある窓を出してマイクを使うプログラム（Discord.exe の名前）、「Meet - …」の題で「Leave call」のボタンのあるページを開いてマイクを使うブラウザ（Edge）で、それぞれ録音を始め、終わると猶予のあとで止める。メインウィンドウを閉じて、トレイにいるときに確かめる。
- **MTG-025** ［単体・結合］ 会議の検出で調べた様子を、様子が変わったときと、会議の開始・終了を確定したときだけ、メモリーに新しいものから 300 件まで残す（様子が変わらない間は、同じ様子を最後に調べた時刻を残す）（この記録はディスクには書かない。デバッグ用のログに書く判定の様子は LOG-005・LOG-010）。残すのは、サービスごとの文脈（アプリの実行ファイルの名前と、窓の識別子）と、立った印の名前と強さ、その回に窓の中の部品を調べたか、確定した出来事とその理由（開始は立っていた印、終了は猶予の経過・打ち消しの印・別の会議への切り替え）。窓やタブの題は、「詳しい記録」（LOG-010）がオンのときだけ残す。API キー・ノートの本文・音声・フルパスは残さない。記録は、製品と同じ間隔（2 秒）と判定で再生でき、`crates/core/tests/fixtures/meetings/` に置いた記録は、書いておいた出来事（開始・終了）がその順に起きることを、回帰テストで確かめる。
- **MTG-026** ［単体・結合・E2E］ 会議の検出の記録（MTG-025）は、設定画面の「デバッグ用のログを保存…」で保存する zip（LOG-011）に、`meeting-detection.json` として入れる。形は、`crates/core/tests/fixtures/meetings/` に置く回帰テストの材料と同じ（JSON の `format` が `kiroscribe-meeting-record/2`）。zip に入れるとき（保存とログの提出の両方）は、窓やタブの題の API キーの形の文字列・URL のクエリ・パスの中の利用者のフォルダの名前を伏せる（LOG-009 と同じ伏せ方）。伏せた記録を再生しても、検出の結果は変わらない。
- **MTG-027** ［単体］ 窓の印は、見えている窓（最小化を含む）だけで立つ。Zoom は、会議の窓（クラス名が ZPContentViewWndClass か ConfMultiTabContentWndClass）を強い印とする。見えない会議の窓と、参加前のプレビューの窓（VideoPreviewWndClass）では立たない。
- **MTG-028** ［単体］ 窓の題と部品の名前は、小文字にし、ダッシュ（— – ― ‐ −）を「-」にそろえて、判定表の語と比べる（「名前と題の比べ方」の節）。ブラウザの窓の題の末尾のブラウザの名前は、区切りが「 - 」でも「 — 」でもよい（Zen の「 — Zen Browser」など）。前に未読の印（「(3) 」「• 」）が付いていてもよい。
- **MTG-029** ［単体］ 窓の中の部品（UI Automation）を調べるのは、デスクトップの会議アプリの見えている窓と、対象のブラウザの見えている窓のうち題が判定表のサービスの題に当たるものと、続いているブラウザの会議の窓だけ。ほかのアプリの窓と、ほかのブラウザの窓の中は調べない。どれかの印が立っているときと会議中は 2 秒ごと、それ以外は 6 秒ごとに調べる。部品は、判定表が使う種類のものの名前と種類だけを読む。
- **MTG-030** ［手動］ Chromium の部品を使う窓（クラス名が Chrome_WidgetWin_1。Discord・Slack・Chromium 系のブラウザ）は、部品を調べる前に、その中の Web の部分の子の窓（クラス名が Chrome_RenderWidgetHostHWND）に MSAA（AccessibleObjectFromWindow）で問い合わせて名前を読み、Web の部分の部品を読めるようにする（同じ窓には 60 秒に 1 回）。Discord を起動してから時間がたってから通話に入っても、入ってから数秒で切断ボタンを読めて、会議の開始になる。
