# リリース前の実機チェックリスト

自動テストでは確かめられない項目（[仕様一覧](spec/README.md)で種類に「手動」がある項目）を、リリースのたびに実機で確かめるための手順です。各手順の末尾に、対応する仕様の ID を書いています。種類に「手動」がある項目がすべてここに載っていることは、`scripts/check-spec-coverage.mjs` が確かめます。

- 所要時間の目安: 全部で約 1 時間 50 分。会議の自動検出（A-7）が 20 分で、いちばん長い。
- 結果は、手順ごとに「OK／NG（起きたこと）」を残します。NG が 1 つでもあれば、リリースを止めます。
- 手順のうち、あとで自動テストに置き換えられるものには「自動化の候補」と書いています。置き換えたら、仕様一覧の種類から「手動」を外し、この一覧からも消します。
- プロキシを通さないと外部に出られない環境での動作は、この一覧の対象外です（仕様一覧の「エラーの扱い」に、未検証の項目として書いています）。

## 準備（10 分）

- Windows 10 または 11 の PC。Kiroscribe を入れたことがない Windows のユーザー（新しく作る）と、1 つ前のバージョンを入れて、ノートを 2〜3 件作ってあるユーザーの 2 つを用意する。
- ヘッドホン、マイク（PC の内蔵と、抜き差しできる USB のものがあるとよい）。
- 通話の相手（2 台目の PC か、スマートフォン）。Google Meet・Slack・Zoom・Teams・Discord のアカウント。
- テスト用の OpenAI・Anthropic の API キー（料金がかかる。全体で数十円ほど）。
- 確かめるインストーラ。公開の前は、CI（main ブランチ）が保存したインストーラを使う。

## A. 公開の前に確かめること

### A-1. インストール（5 分）

1. 新しい Windows のユーザーで、インストーラ `Kiroscribe_<バージョン>_x64-setup.exe` を実行する。
2. 「Windows によって PC が保護されました」と出たら、「詳細情報」→「実行」を選ぶ。
3. 管理者のパスワードを求められずに、最後まで進むことを確かめる。インストーラの表示が日本語であることを確かめる。
4. インストールが終わったら Kiroscribe を起動し、メインウィンドウが出ることを確かめる。設定の「このアプリについて」のバージョンが、リリースするバージョンであることを確かめる。
5. 1 つ前のバージョンが入っているユーザーで、同じインストーラを実行する。起動して、前に作ったノートと設定、API キーの「設定済み」が残っていることを確かめる。

対応: REL-001、REL-002、REL-009

### A-2. API キーの保存先（3 分）

1. 設定を開き、OpenAI と Anthropic のキーを入れて、それぞれ「保存」を押す。「設定済み」になり、入力欄が空になることを確かめる。保存先として「Windows 資格情報マネージャー」と表示されていることを確かめる。
2. Windows の「資格情報マネージャー」→「Windows 資格情報」を開き、「Kiroscribe」を含む名前の汎用資格情報が 2 つ（openai-api-key、anthropic-api-key）あることを確かめる。
3. Kiroscribe を終了して起動し直し、「設定済み」のままであることを確かめる。

対応: KEY-004

### A-3. マイクの一覧と、手動の録音（7 分）

1. 設定の「マイク」に、「既定のマイク（<デバイスの名前>）」と、つないでいるマイクが名前で並んでいることを確かめる。
2. 新しいノートを作り、「録音を開始」を押す。「録音中」になり、経過時間が進むことを確かめる。
3. ヘッドホンをして、マイクに向かって 2〜3 文を話す。数秒後に、話した内容が「自分」として表示されることを確かめる。話している間、「自分」の入力の大きさのバーが動くことを確かめる。
4. PC で人が話している動画などを再生する。その内容が「相手」として表示されること、「相手」のバーが動くことを確かめる。
5. 「一時停止」を押して話す。その間の内容が表示されないことを確かめる。「再開」を押して話すと、また表示されることを確かめる。
6. 「停止」を押す。「文字起こしを仕上げています…」のあと、最後に話した内容まで表示されることを確かめる。

対応: SET-006、REC-001、TRN-022

### A-4. 相手の声を取り込まない場合（4 分）

1. 設定の「相手の声（PC から流れる音声）も取り込む」をオフにして保存する。録音を始め、PC で動画を再生しても「相手」の文字起こしが出ないこと、バーが「自分」だけであること、文字起こしのパネルの下に「相手の声は取り込んでいません（マイクのみ）」と出ることを確かめる。
2. 設定をオンに戻す。Windows の「サウンド」で出力デバイスをすべて無効にして（できる環境の場合）、録音を始める。「相手の声は取り込まず、マイクだけで録音します」と知らせが出て、マイクの録音は続くことを確かめる。出力デバイスを元に戻す。

対応: REC-017、REC-018

### A-5. マイクの異常（6 分）

1. 設定で USB のマイクを選んで保存する。USB のマイクを抜いてから録音を始める。「選択したマイクが見つからないため、既定のマイクで録音します」と知らせが出て、内蔵のマイクで録音できることを確かめる。設定のマイクの欄が「（見つからないデバイス）」になっていることを確かめる。
2. USB のマイクをつなぎ、それで録音を始めてから、録音中に抜く。音声デバイスのエラーの知らせが出ること、アプリが落ちないこと、「停止」を押せることを確かめる。
3. Windows の「サウンド」で入力デバイスをすべて無効にして、録音を始める。録音が始まらず、「マイクが見つかりません。接続と Windows のプライバシー設定（マイクへのアクセス）を確認してください」と知らせが出ることを確かめる。入力デバイスを元に戻す。

対応: REC-019、REC-020、REC-021

### A-6. 議事録と AI チャット（5 分）

1. A-3 で録音したノートに、メモを 2〜3 行書く。「議事録を作成」を押す。議事録が少しずつ表示され、終わるとタイトルが付く（空だった場合）ことを確かめる。メモに書いた行が濃く表示されることを確かめる。
2. 「AI チャット」を開き、「この会議で決まったことは？」を押す。回答が少しずつ表示され、内容が録音した会話に沿っていることを確かめる。
3. 設定で Claude のモデルを別のものに変えて保存し、もう一度質問して、回答が返ることを確かめる（選択メニューの 4 つのモデルのうち、既定と、もう 1 つ）。

対応: MIN-020、CHT-013

### A-7. 会議の自動検出（20 分。1 つのサービスにつき約 4 分）

Google Meet（ブラウザ）、Slack ハドル、Zoom、Teams、Discord のそれぞれで、次を行う。メインウィンドウは閉じて（トレイに残して）おく。

1. 相手と会議・通話に入る。数秒（4〜6 秒）後に、画面の右下にポップアップが出て、サービスの名前と「自動で録音・文字起こしを始めました」が表示されることを確かめる。ポップアップが出ても、会議のウィンドウの入力（フォーカス）が奪われないことを確かめる。
2. ポップアップの上部をドラッグして、動かせることを確かめる。
3. 「ノートを開く」を押す。メインウィンドウが手前に出て、「<サービスの名前> <月>/<日> <時>:<分>」のノートが開き、自分と相手の文字起こしが増えていくことを確かめる。
4. （ブラウザの会議の場合）別のタブに切り替えて 30 秒待ち、録音が続いていることを確かめる。
5. 会議・通話を抜ける。約 20 秒後にポップアップが出て、「文字起こしを仕上げています…」のあと「録音を停止しました」に変わることを確かめる。そのまま 30 秒待つと、ポップアップが自動で閉じることを確かめる。

サービスのうち 1 つでは、5 の代わりに、会議の途中でポップアップの「停止」を押して、「録音を停止しました。文字起こしを仕上げています…」のあと「録音を停止しました」に変わることを確かめる。別の 1 つでは、止まったあとの「議事録を作成」を押して、メインウィンドウで議事録の作成が始まることを確かめる。

対応: MTG-023、POP-001、POP-012

### A-8. トレイと常駐（5 分）

1. 手動で録音を始めてから、メインウィンドウを × で閉じる。タスクトレイに Kiroscribe のアイコンが残ること、アイコンに重ねると「Kiroscribe（会議の自動検出）」と出ることを確かめる。
2. トレイのアイコンを左クリックする。メインウィンドウが手前に出て、録音が続いていた（経過時間が進み、閉じていた間の文字起こしがある）ことを確かめる。ウィンドウを最小化してから左クリックしても、手前に出ることを確かめる。
3. トレイのアイコンを右クリックする。「Kiroscribe を開く」「会議を検出したら自動で録音」（チェック付き）「Kiroscribe を終了」が並ぶことを確かめる。
4. 「会議を検出したら自動で録音」を選ぶ。もう一度右クリックするとチェックが外れていること、設定画面を開くと「会議の自動検出」がオフになっていることを確かめる。設定画面でオンに戻して保存し、メニューのチェックが付くことを確かめる。
5. 録音中のまま、マイクに向かって 1 文を話し、すぐに「Kiroscribe を終了」を選ぶ。数秒後にアイコンが消えることを確かめる。起動し直して、最後に話した 1 文がノートに残っていることを確かめる。

対応: TRY-001、TRY-002、TRY-003、TRY-004、TRY-005

### A-9. 二重起動（1 分）

1. メインウィンドウを閉じて（トレイに残して）、スタートメニューから Kiroscribe をもう一度起動する。メインウィンドウが出て、トレイのアイコンが 1 つのままであることを確かめる。

対応: TRY-006

### A-10. Windows の起動時の自動起動（6 分）

1. 設定の「Windows の起動時に Kiroscribe を起動する」がオンであることを確かめる。タスクマネージャーの「スタートアップ アプリ」に Kiroscribe があることを確かめる。
2. Windows にサインインし直す（または再起動する）。メインウィンドウは出ず、トレイにアイコンがあることを確かめる。トレイのアイコンを左クリックして、ウィンドウが出ることを確かめる。
3. 設定でオフにして保存する。「スタートアップ アプリ」から Kiroscribe がなくなる（または無効になる）ことを確かめる。サインインし直して、Kiroscribe が起動していないことを確かめる。確かめたら、オンに戻す。

対応: TRY-008、TRY-009

### A-11. ヘルプ（2 分）

1. インターネットにつないだ状態で、サイドバーの「？」を押す。「使い方」が表示され、出どころの注記（「オンラインの最新版を取得できないため…」）が出ていないことを確かめる。
2. 「リリースノート」に切り替える。公開済みのリリースが新しい順に並ぶことを確かめる。「GitHub」のリンクを押すと、既定のブラウザでリリースのページが開き、Kiroscribe の画面はそのままであることを確かめる。
3. ネットワークを切ってから、ヘルプを開き直す。注記が出て、内容は表示されることを確かめる。ネットワークを戻す。

対応: HLP-015

### A-12. 署名の合わない更新を入れないこと（10 分。E2E テスト用のビルドを使う。自動化の候補）

1. 手元の PC で、テスト用の鍵で署名したインストーラと latest.json を置いた配布元（手元の HTTP サーバー）を用意する。latest.json の署名を、別のファイルの署名に書き換えておく。
2. E2E テスト用のビルド（`npm run build:e2e` で作る。[development.md](development.md) の「E2E テスト」）を使う。空の作業フォルダを用意し、その中の `config.json` に `{ "updateEndpoint": "<手元の latest.json の URL>", "updatePubkey": "<テスト用の公開鍵>" }` と書き、環境変数 `KIROSCRIBE_E2E_DIR` にその作業フォルダの絶対パスを入れて起動する。
3. 設定の「更新を確認」を押し、新しいバージョンの知らせが出ることを確かめる。「更新して再起動」を押す。ダウンロードのあと、「ダウンロードしたファイルの署名を確認できなかったため、更新を中止しました」と出て、アプリが終了せず、バージョンが変わらないことを確かめる。
4. 起動し直して、設定の「新しいバージョンを自動でインストールする」をオンにして保存し、メインウィンドウを閉じて数分待つ。アプリが再起動せず、バージョンが変わらないこと、署名についての知らせが出ないことを確かめる（トレイから開いて確かめる）。

対応: UPD-010、SEC-010、UPD-027

## B. 公開の直後に確かめること

アプリ内の更新は、公開された「最新のリリース」を見に行くため、公開の前には実物で確かめられません。公開したらすぐに確かめ、NG の場合はリリースを取り下げます（取り下げると、利用者のアプリは 1 つ前のリリースを最新として扱います）。

### B-1. リリースの成果物（5 分）

1. GitHub のリリースのページに、インストーラ（`Kiroscribe_<バージョン>_x64-setup.exe`）、署名（`.exe.sig`）、`latest.json`、`SHA256SUMS.txt` の 4 つが付いていることを確かめる。本文が CHANGELOG.md のそのバージョンの節と同じであることを確かめる。
2. `latest.json` を開き、`version` がリリースしたバージョンで、`url` がこのリリースのインストーラを指していることを確かめる。
3. インストーラをダウンロードし、PowerShell の `Get-FileHash <ファイル> -Algorithm SHA256` の結果が `SHA256SUMS.txt` と同じであることを確かめる。`gh attestation verify <ファイル> --repo s-tabana/kiroscribe` が成功することを確かめる。
4. ハイフンの付くバージョン（ベータ版など）の場合は、リリースが「プレリリース」になっていて、1 つ前のバージョンのアプリで「更新を確認」を押しても「最新のバージョンです」と出ることを確かめる。

対応: REL-008

### B-2. 1 つ前のバージョンからの更新（8 分）

1. 1 つ前のバージョンを、Windows の起動時の自動起動で動かしておく（サインインし直して、ウィンドウが出ていない状態にする）。トレイからウィンドウを開く。
2. 設定の「更新を確認」を押す。新しいバージョンの知らせと「<バージョン> の変更点」が出ることを確かめる。
3. 録音を始めてから「更新して再起動」を押す。「録音を停止してから更新してください」と出て、更新が始まらないことを確かめる。録音を止める。
4. 「更新して再起動」を押し、確認のダイアログで OK を選ぶ。進み具合が表示され、「更新をインストールしています。まもなく再起動します…」のあと、アプリが終了することを確かめる。インストーラが、操作を求めずに進むことを確かめる。
5. 新しいバージョンが自動で起動し、メインウィンドウが出ることを確かめる（自動起動で動いていた場合でも出る）。設定のバージョンが新しくなっていること、ノート・設定・API キーが残っていることを確かめる。

対応: UPD-010、UPD-012、UPD-013

### B-3. 自動更新（15 分）

自動更新の入った最初のバージョン（0.3.0）を公開する時点では、それより新しいバージョンがないため、この手順は A-12 と同じ方法（開発用のビルドと手元の配布元。署名は正しいものにする）で確かめます。その次のバージョンからは、公開の直後に、1 つ前のバージョンの実物で確かめます。

1. 1 つ前のバージョンで、設定の「新しいバージョンを自動でインストールする」をオンにして保存する。メインウィンドウを開いたままにする。
2. 設定の「更新を確認」を押す。新しいバージョンが見つかってダウンロードが終わると、サイドバーの下と設定画面に「新しいバージョン <バージョン> の準備ができました。ウィンドウを閉じると更新します」と「今すぐ更新」が出ることを確かめる。そのまま数分待っても、アプリが再起動しないことを確かめる。
3. 録音を始めてから、メインウィンドウを閉じる。数分待っても、アプリが再起動しないこと、録音が続いていることを確かめる（トレイから開いて確かめる）。録音を止める。
4. メインウィンドウを閉じる。1〜2 分のうちにアプリが新しいバージョンで起動し直し、メインウィンドウは出ず、トレイにアイコンがあることを確かめる。
5. トレイからメインウィンドウを開く。サイドバーの下に「バージョン <バージョン> に更新しました」と表示されること、「リリースノート」を押すとリリースノートが開くことを確かめる。ウィンドウを閉じて開き直し、もう表示されないことを確かめる。
6. 設定をオフに戻して保存する。

対応: UPD-024、UPD-027（署名の合わない場合は A-12 で確かめる）
