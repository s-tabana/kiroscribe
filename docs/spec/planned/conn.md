# CONN: サービスの接続

ログインが要るサービスの中を、会議の相棒（[cmp.md](cmp.md)）が探すための接続（段階3）。最初に対応するのは Google Drive と Slack。サービスごとに「接続」で一度ログインし、利用者がキーを手で入れることはない。この節の未決の点は、末尾の「未決の点」にある。

## 接続と切断

- **CONN-001** ［単体・E2E］ 設定の「会議の相棒」の欄に、サービスごとに接続の状態（「未接続」「接続済み: <アカウント>」「接続し直してください」）と、「接続」または「切断」のボタンを表示する。
- **CONN-021** ［単体・E2E］ 「接続」を押すと、まず確認のダイアログで、送り先と送るものと費用を示し、OK のときだけ接続に進む。送るものは、<サービス> には検索語、Anthropic には見つかった資料の題名・送るための場所・抜粋（CMP-013・CMP-043）。費用は、Anthropic の分は CMP-036 の目安に含まれることを示し、サービス側の料金は、段階3 を始める条件（[開発の計画](../../plan.md)）で確かめた結果に合わせて示す。
- **CONN-002** ［単体・結合］ 確認のダイアログ（CONN-021）で OK を押すと、既定のブラウザでサービスのログインと許可の画面を開く。許可されると、ブラウザは PC の中だけで受ける戻り先（`http://127.0.0.1` か `http://localhost` のアドレス）に戻り、Kiroscribe がトークンを受け取って「接続済み」にする。ブラウザには「Kiroscribe に戻ってください」と表示する。戻り先のポートを毎回選ぶか、決まったポートにするかは、サービスごとに、段階3 を始める条件（[開発の計画](../../plan.md)）で確かめた結果に合わせる。Slack がこの形の戻り先を受け付けないと分かったときは、PR 3-0 の前に、未決 8 と合わせて Slack の部分を見直す。
- **CONN-003** ［単体・結合］ 接続には、PKCE（要求ごとに作る確認の値）と state（応答の取り違えを防ぐ値）を使い、値の合わない応答は捨てる。許可されないまま 5 分たったとき、ブラウザで拒否されたときは、接続を取りやめて「接続できませんでした（理由）」と表示する。
- **CONN-004** ［単体・結合］ 「切断」を押すと確認のダイアログを出し、OK ならサービスにトークンの取り消しを送り、PC の中のトークンを消して「未接続」に戻す。取り消しの通信に失敗しても、PC の中のトークンは消す。
- **CONN-005** ［単体］ 接続済みのサービスごとに「このサービスも探す」をチェックで切り替えられる（接続した直後はオン）。未接続のサービスと、オフにしたサービスには、検索語を送らない。

## トークンの保存

- **CONN-006** ［結合］ Windows では、サービスのトークンを Windows 資格情報マネージャーに、KEY-004 と同じ形の汎用資格情報として保存する（名前は「google-drive-token.Kiroscribe」「slack-token.Kiroscribe」）。保存するのは、更新用のトークン（refresh token）とアカウントの表示名だけ。期限の短いアクセストークンは、メモリにだけ置く。
- **CONN-007** ［単体］ Windows 以外（開発用）では、KEY-005 と同じく secrets.json に保存する。
- **CONN-008** ［単体・結合］ トークンは、画面（WebView）に返さず、データベース・設定・ログ・知らせの文に書かない。サービスが返したエラーの文にトークンの形の文字列（`ya29.`・`1//`・`xoxp-`・`xoxe-`・`xoxe.` で始まるもの）があれば、その部分を「（トークンは表示しません）」に置き換える。
- **CONN-009** ［単体・結合］ トークンは、受け取ったサービスの API（Google は `https://oauth2.googleapis.com` と `https://www.googleapis.com`、Slack は `https://slack.com/api`）にだけ送る。
- **CONN-010** ［単体・結合］ 更新用のトークンで新しいアクセストークンを受け取るたびに、サービスが新しい更新用のトークンを返したら保存し直す。更新用のトークンが使えないとき（期限切れ・取り消し）は、そのサービスを「接続し直してください」にして探し先から外し、録音中なら「<サービス> に接続し直してください」と 1 回だけ知らせる。相棒のほかの探し先は動く。

## Google Drive

- **CONN-011** ［結合］ Google Drive には、読み取りだけの許可（`https://www.googleapis.com/auth/drive.readonly`）で接続する。アカウントの表示には、Drive の `about.get` が返すメールアドレスを使う。
- **CONN-012** ［結合］ 検索語で、ごみ箱にないファイルの名前と本文を探し（Drive API の `files.list` に `fullText contains` の条件）、更新日時の新しい順に 5 件までを候補にする。
- **CONN-013** ［結合］ 候補のうち、Google ドキュメント・スプレッドシート・スライドの上位 3 件は、本文をテキストとして取り出し（`files.export`）、抜粋を作る（IDX-015 と同じ作り方）。それ以外のファイルは、名前だけの候補にする。
- **CONN-014** ［単体］ Google Drive の資料は、探し先の名前を「Google Drive」、題名をファイル名、場所をファイルの URL（`webViewLink`）にする。コピーのボタンは「URL をコピー」（URL を書き込む）、開くボタンは「ブラウザで開く」（既定のブラウザで開く。SEC-008 に従う）にする。

## Slack

- **CONN-015** ［結合］ Slack には、利用者として検索する許可（ユーザートークンの `search:read`）だけで接続する。ボットは使わない。アカウントの表示には、`auth.test` が返すワークスペース名と利用者名を使う。
- **CONN-016** ［結合］ 検索語でメッセージを探し（`search.messages`）、CONN-022 で除いたあとの、関連の高い順に 5 件までを候補にする。抜粋は、メッセージの本文の 600 文字まで。
- **CONN-017** ［単体］ Slack の資料は、探し先の名前を「Slack」、題名をメッセージの本文の先頭 40 文字、場所をチャンネル名・投稿者・日時とメッセージの URL（`permalink`）にする。コピーのボタンは「URL をコピー」（URL を書き込む）、開くボタンは「ブラウザで開く」（既定のブラウザで開く。SEC-008 に従う）にする。Anthropic へ送る場所では、permalink のクエリとフラグメントを除く（CMP-043）。表示・コピー・開くには、除かない permalink を使う。
- **CONN-022** ［単体・結合］ Slack の検索の結果は、公開チャンネルのメッセージだけを候補にし、DM・グループの DM・非公開チャンネルのメッセージは、表示・保存・Anthropic への送信の前に除く。「非公開チャンネルと DM も探す」（初期値はオフ）をオンにしたときだけ含める。オンにするときは、確認のダイアログで、それらのメッセージの本文の一部が Anthropic へ送られることを示し、OK のときだけオンにする。

## 検索の通信

- **CONN-018** ［結合］ サービスの検索は 8 秒で打ち切り、打ち切ったサービスの候補なしで選択（CMP-013）に進む。
- **CONN-019** ［単体・結合］ サービスに送るのは検索語だけで、発言そのものは送らない。
- **CONN-020** ［手動］ 実際の Google Drive と Slack のアカウントで、接続・検索（会議中に資料名のバッジが出る）・切断ができる。

## 未決の点

### 未決 7: Google の OAuth クライアントの公開状態

決めること: Google Drive に接続するための OAuth クライアントを、どの状態で使うか。
Google は、テスト中のアプリの許可を 7 日で失効させる（出典は下記）。
推奨案で書いている項目: CONN-010、CONN-011。

| 案 | 変わること |
| --- | --- |
| A. テスト中のまま使い、使う人をテストの利用者に登録する（推奨） | すぐ使える。登録できるのは 100 人まで。7 日ごとに「接続し直してください」になる |
| B. 本番に公開し、制限付きのスコープ（`drive.readonly`）の審査を受ける | 再接続は要らない。審査に時間がかかる。資料の抜粋を Anthropic に送るため、第三者の安全性の評価を求められる可能性がある（確認不可。PR 3-0 の前に確かめる） |
| C. Google Workspace の組織の内部アプリとして登録する | 組織の人だけが使え、審査は要らない。組織が Google Workspace を使っている場合に限る |

出典（確認日 2026-11-27）: Google Cloud のヘルプ「Manage App Audience」（https://support.google.com/cloud/answer/15549945）、Google Drive API の「Choose Google Drive API scopes」（https://developers.google.com/workspace/drive/api/guides/api-specific-auth）。

### 未決 8: Slack アプリの登録先と配り方

決めること: Slack に接続するための Slack アプリを、どこに作り、どう配るか。
PKCE を使うデスクトップの接続では、ボットの許可を求めることはできず、更新用のトークンは 30 日で失効する（出典は下記）。
推奨案で書いている項目: CONN-015。
Slack が、PKCE の接続の戻り先に `http://127.0.0.1` と `http://localhost` のどちらのアドレスを受け付けるか（任意のポートか、決まったポートの登録が要るか）は確認不可（2026-11-27 時点）。段階3 を始める条件で確かめ、結果をこの節に書き足す。どちらも受け付けないときは、PR 3-0 の前に、CONN-002 の Slack の部分と合わせて、この未決の案を見直す。

| 案 | 変わること |
| --- | --- |
| A. オーナーのワークスペースに 1 つ作り、公開配布を有効にする（推奨） | 1 つのアプリで、ほかのワークスペースの人も接続できる。ワークスペースの設定によっては、管理者の承認が要る |
| B. 使う人のワークスペースごとに、内部アプリを作る | ワークスペースの外に配らずに済む。アプリの ID がワークスペースごとに違うため、ID を選ぶ仕組みが要る |

Slack は 2025 年 5 月から、Marketplace にない配布アプリについて、一部の API（`conversations.history`・`conversations.replies`）の利用回数を下げた。相棒が使う `search.messages` は対象に含まれていない。Slack の API の規約で、取得したメッセージを AI に送ることの扱いは確認不可（2026-11-27 時点）。PR 3-0 を始める前に確かめる（[開発の計画](../../plan.md)の「段階3 を始める条件」）。

出典（確認日 2026-11-27）: Slack「Using PKCE」（https://docs.slack.dev/authentication/using-pkce）、「search.messages」（https://docs.slack.dev/reference/methods/search.messages）、「Rate limit changes for non-Marketplace apps」（https://docs.slack.dev/changelog/2025/05/29/rate-limit-changes-for-non-marketplace-apps）。
