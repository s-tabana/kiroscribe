# 開発の計画

会議の相棒を、3 つの段階に分けて作ります。段階ごとに next で開発し、段階が終わったら main に取り込んでリリースします。仕様は[予定の仕様](spec/planned/)（[会議の相棒](spec/planned/cmp.md)・[資料の索引](spec/planned/idx.md)・[サービスの接続](spec/planned/conn.md)）にあります。

## 進め方

- 各 PR は、実装する項目を `docs/spec/planned/` から `docs/spec/` の同じ名前のファイルに移し、テストと一緒に入れます（ID は変えません）。
- 画面が呼ぶコマンドと待ち受けるイベントは、本体への登録と画面からの利用を同じ PR に入れます（IPC-001・IPC-005 の一致の検査が、PR ごとに通るようにするため）。
- 移す項目のテストが、まだ移していない項目の機能を前提にしないように、項目を割り当てます。バッジ・知らせ・録音の状態に関わる項目は、画面と録音につなぐ PR（1-3）に置きます。
- 項目でない文と表（目安の表など）は、その節の項目を初めて移す PR で移し、まだ作らない探し先の部分は除きます。ただし、CMP-036 が参照する「費用の目安」と「PC の外に送るもの」の節の文と表は、CMP-036 と一緒に PR 1-1 で移します。まだ移していない項目の ID は書かずに移し、その項目を移す PR で足します。
- 設定の項目を足す PR は SET-001（初期値）・SET-004（古い設定の読み込み）と IPC-003（設定の型）を、データの保存先や形を変える PR は DAT-001・DAT-002 を、コマンドやイベントを足す PR は IPC-001〜IPC-005 を、同じ PR で直します。
- 種類に「手動」がある項目を移す PR は、[リリース前の実機チェックリスト](release-checklist.md)にも手順を足します。
- 移す項目に関わる未決の点は、その PR を始める前にオーナーが決めます（「未決の点と決める時期」）。

## 段階3: Google Drive と Slack

区切りは、「接続」で一度ログインしたサービスの中も、相棒が探すことです。最初に Google Drive、次に Slack をつなぎます。

### 段階3 を始める条件

PR 3-0 を始める前に、オーナーが次を確かめ、結果を [conn.md](spec/planned/conn.md) の未決 7・8 に書き足します。確かめた結果で、未決 7・8 と未決 2（サービスの資料の抜粋を送るか）を決めます。

- Google と Slack のそれぞれの PKCE の接続で、戻り先に `http://127.0.0.1` と `http://localhost` のどちらのアドレスを使えるか、使えるなら任意のポートか、ポートを固定して登録する必要があるか（CONN-002）。Slack がどちらも使えないときは、PR 3-0 の前に、未決 8 と CONN-002 の Slack の部分を見直す。
- Google の API サービスのユーザーデータに関するポリシーで、Google Drive から取り出した本文の抜粋を Anthropic に送れるか、その条件。
- Slack の API の規約で、取得したメッセージの本文を Anthropic に送れるか、その条件。
- Google の審査で、`drive.readonly` を使うときに求められること（テスト中・本番・組織の内部アプリのそれぞれ）。
- Google Drive API と Slack の API の利用に、料金がかかるか（CONN-021 の表示）。

## 未決の点と決める時期

選択肢と推奨案は、それぞれの仕様のファイルの末尾にあります。決めた PR で、推奨案で書いている項目の文を選んだ案に合わせ（推奨案のままなら直しません）、その未決の節を予定の仕様から消します。選んだ案と理由は、その PR の説明に書きます。

## 会議の検出の作り替え（判定表）

会議の段階とは別に、会議の自動検出（[MTG](spec/mtg.md)）を、サービスごとの判定表で決める方式に作り替えます。マイクの使用だけでは、ミュートのままの参加を見逃し、会議でないマイクの使用でも録音を始めてしまうためです。判定表は、2026-11-28 の実機の測定（Google Meet・Slack ハドル・Discord・Zoom。Teams は未測定）で合った印と、外れた点の対策をもとにしています。

| PR | 中身 | 直す項目 |
| --- | --- | --- |
| 会議 1 | 判定表（組み込み）と、窓・窓の中の部品（UI Automation）・録音と再生のオーディオのセッションの読み取り、開始・継続・終了の判定、2 つの会議が重なったときの切り替え、検出の記録（`kiroscribe-meeting-record/3`）とログ、確認用の道具（`meeting_probe`）の作り直し、E2E。ConsentStore は使わなくする。PR #18（オーディオのセッションの読み取りと確認用の道具）の変更を含め、PR #18 は閉じる | MTG-001〜MTG-010、MTG-020、MTG-023〜MTG-030、SEC-013、LOG-005、LOG-010 |
| 会議 2 | 設定で、判定の対象に足すブラウザを実行ファイルの名前で入力できるようにする（設定の欄、保存、判定への反映） | MTG-002、SET-001、SET-004、SET-021（新しい項目）、IPC-003 |

- 会議 2 は会議 1 の上に作り、会議 1 を next に取り込んでから、取り込み先を next に替えます。
- 2 つを next に取り込んだら、Windows 実機の確認係が、[会議の検出の実機の確認](meeting-detection-check.md)の手順で、サービスごとに判定を確かめます。外れた点は、記録（`meeting-detection.json`）を回帰テストに加えてから、判定表を直します。
