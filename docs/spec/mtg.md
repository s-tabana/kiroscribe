# MTG: 会議の自動検出

会議が始まったことを検出して自動で録音し、終わったら止める（Windows）。

- **MTG-001** ［単体］ 次のデスクトップアプリがマイクを使っている間は、会議中とみなす: Slack（slack.exe、またはパッケージ名が 91750D7E.Slack_（Microsoft Store 版）・com.tinyspeck.slackdesktop_（MSIX 版）で始まるもの）、Zoom（zoom.exe・cpthost.exe）、Teams（ms-teams.exe・ms-teams_modulehost.exe・teams.exe、またはパッケージ名が MSTeams_・MicrosoftTeams_ で始まるもの）、Discord（discord.exe・discordptb.exe・discordcanary.exe・discorddevelopment.exe）。大文字小文字は区別しない。
- **MTG-002** ［単体］ ブラウザ（chrome・msedge・firefox・brave・vivaldi・opera・arc）がマイクを使っていて、そのブラウザ自身の表示中のウィンドウのタイトルが会議のものなら、会議中とみなす（マイクを使っているのとは別のブラウザのウィンドウのタイトルでは、会議とみなさない）。Google Meet は「google meet」「meet.google.com」「 - meet - 」を含むか、「meet - 」「meet – 」「meet: 」「meet：」で始まるもの。Slack は「slack」と「huddle」か「ハドル」を含むもの（ハドルを別のウィンドウにしたときの「Huddle: 相手 - ワークスペース - Slack」など）。ハドルを示す語のない Slack の画面（「相手 - ワークスペース - Slack」など）は、会議とみなさない。Teams は「microsoft teams」と「meeting」「会議」「call」「通話」のどれかを含むもの。Zoom は「zoom」と「meeting」か「ミーティング」を含むもの。Discord は、Discord の画面のタブ名の形のもの（「Discord | 」で始まる、または「 | Discord」「 - Discord」で終わる。前に未読の印「(3)」「•」が付いていても、後ろにブラウザの名前が付いていてもよい）。タイトルに「discord」を含むだけのページ（Discord についての記事や検索結果など）は、会議とみなさない。
- **MTG-003** ［単体］ 会議アプリ以外がマイクを使っていても、ブラウザが会議以外のサイトでマイクを使っていても、会議とはみなさない。会議アプリと一緒に入る更新・起動のためのプロセス（Slack の update.exe、Teams の ms-teamsupdate.exe・msteams_autostarter.exe）、ほかのアプリも使う部品（msedgewebview2.exe、Zoom の SDK 用の zcscpthost.exe）、会議アプリのパッケージ名に似ているだけのものも、会議とはみなさない。
- **MTG-004** ［単体］ 会議のページを開いているだけ（ブラウザがマイクを使っていない）では、会議とはみなさない。以前マイクを使っていて、いまは使っていないアプリも対象にしない。
- **MTG-005** ［単体］ Kiroscribe 自身がマイクを使っていること（録音中）は、判定に入れない。
- **MTG-006** ［単体］ デスクトップの会議アプリとブラウザの会議の両方が当てはまるときは、デスクトップの会議アプリとして扱う。
- **MTG-007** ［単体］ 2 秒ごとに調べ、同じ会議が 4 秒続けて検出されたら「会議の開始」とする。途中で検出が途切れたら数え直す。開始は 1 つの会議につき 1 回だけ。
- **MTG-008** ［単体］ 会議が検出されなくなってから 20 秒たったら「会議の終了」とする。20 秒以内に戻れば、続いているものとして扱う。
- **MTG-009** ［単体］ ブラウザの会議は、始まったあとで別のタブに切り替えても、その会議を始めたブラウザがマイクを使っている間は続いているとみなす（別のブラウザがマイクを使っていても、続きにはしない）。デスクトップアプリの会議は、そのアプリがマイクを使っている間だけ続いているとみなす（ほかのアプリがマイクを使っていても続きにはしない）。
- **MTG-010** ［単体・結合］ 会議が続いている間に別の会議が検出されても、新しい会議の開始にはしない。会議が終わって 20 秒たたないうちに別のアプリの会議が始まったとき（4 秒続けて検出されたとき）は、前の会議の録音を止めて、新しいノートで録音を始める。前の録音の文字起こしの仕上げが終わってから、次の録音を始める（仕上げ中でも、次の会議の録音を取りこぼさない）。同じアプリの会議がまた検出されたときは、前の会議の続きとして扱う。
- **MTG-011** ［単体・結合・E2E］ 会議の開始を検出し、設定の「会議の自動検出」がオンで、録音していなければ、ノートを「<会議の名前> <月>/<日> <時>:<分>」（例「Google Meet 11/20 15:04」）のタイトルで作り、録音と文字起こしを始め、ポップアップで知らせる。作ったノートは、メインウィンドウの一覧の先頭にすぐ加わる。
- **MTG-012** ［結合・E2E］ 設定の「会議の自動検出」がオフのときは、会議を検出しても何もしない（ノートを作らず、ポップアップも出さない）。
- **MTG-013** ［結合］ すでに録音中（手動の録音を含む。仕上げ中も含む）に会議の開始を検出したときは、何もせず、いまの録音を続ける。
- **MTG-014** ［単体・結合］ 会議の開始を検出したとき OpenAI の API キーが未設定なら、ノートを作らず、ポップアップで「OpenAI の API キーが設定されていないため、自動で録音できませんでした」と知らせる。
- **MTG-015** ［結合］ ノートを作ったあとで録音を始められなかったとき（マイクがない、など）は、ポップアップで理由を知らせ、作った空のノートは消す（メインウィンドウの一覧にも加えない）。
- **MTG-016** ［単体・結合・E2E］ 会議の終了を検出したとき、自動で始めた録音が続いていれば、ポップアップに「仕上げ中」を表示して録音を止め、残りの文字起こしが終わったらポップアップに「停止」を表示する。
- **MTG-017** ［結合］ 手動で始めた録音は、会議が終わっても止めない。自動で始めた録音を利用者が先に止めていた場合、会議が終わっても何もしない。
- **MTG-018** ［結合］ 会議の途中で設定の「会議の自動検出」をオフにしても、自動で始めて続いている録音は、会議の終了で止まる。
- **MTG-019** ［結合］ 設定の「会議の自動検出」をオフからオンにした時点（設定画面での保存、またはトレイのメニュー）で会議中なら、その会議の録音を始める。自動で始めた録音を利用者が止めたあと、または手動の録音を止めたあとは、同じ会議が続いていても録音を始め直さない（録音を始めるのは、会議の開始を検出したときと、オフからオンに変えたときだけ）。
- **MTG-020** ［単体・結合］ マイクを使っているアプリは、第一に Windows のオーディオのセッションから読み取る。すべての有効な録音デバイスについて、アプリごとの録音のセッションを読み、状態が Active（いま録音している）のプロセスを「使用中」とする（同じアプリのセッションが複数あれば、どれかが Active なら使用中）。判定（MTG-001〜MTG-003）には、そのプロセスのパッケージファミリー名（Microsoft Store 版・MSIX 版のアプリ）が会議アプリに当たればそれを、当たらなければ実行ファイルのパスを使う。MTG-003 の補助プロセスは実行ファイル名で除外する。読むのはプロセスとセッションの状態だけで、音声や音量は読まない。録音デバイスの一覧を取得できない場合、全デバイスのセッション一覧を取得できない場合、またはセッションがあっても全件の情報を取得できない場合に限り、補助として Windows が記録しているマイクの使用状況（ConsentStore。アプリごとの使用開始・終了の時刻）から読み取り、使用を開始していて、まだ終了していないものを「使用中」とする。一部の取得に失敗した場合は、取得できた一覧で判定する。録音デバイスが 0 台の場合と、正常に空の一覧を取得した場合は、どちらもマイクを使用しているアプリがないと判定する。
- **MTG-021** ［単体］ Windows 以外では、会議を検出しない。
- **MTG-022** ［E2E］ E2E テスト用のビルド（cargo の feature `e2e`）では、実際の検出の代わりに、作業フォルダの `meeting.txt` に書いた会議アプリ（googleMeet・slackHuddle・zoom・teams・discord）の会議中として扱う（ファイルがない・空なら会議中ではない）。配布するビルドには、この差し替えは入らない（SEC-012）。
- **MTG-023** ［手動］ 実際の Google Meet・Slack ハドル・Zoom・Teams・Discord で、会議に入ると数秒後に自動で録音が始まり、抜けると約 20 秒後に止まる（リリースのたびに、Google Meet と、ほかの 1 つを順番に確かめる）。
- **MTG-024** ［E2E］ 会議の検出は、製品と同じ仕組みで動く: デスクトップの会議アプリの名前（zoom.exe・discord.exe など）のプログラムが本物のマイクを使い始めると、Windows のオーディオのセッションから読み取って録音を始め、使い終わると猶予のあとで止める。ブラウザ（Edge）が「Meet - …」の題のページで本物のマイクを使い始めたときも同じ。メインウィンドウを閉じて、トレイにいるときに確かめる。
- **MTG-025** ［単体・結合］ 会議の検出で調べた様子を、様子が変わったときと、会議の開始・終了を確定したときだけ、メモリーに新しいものから 300 件まで残す（この記録はディスクには書かない。デバッグ用のログに書く判定の様子は LOG-005・LOG-010）。残すのは、マイクを使ったアプリの実行ファイルの名前（利用者の名前を含むフルパスは残さない）かストアアプリのパッケージ名と、いまマイクを使っているブラウザのウィンドウのタイトルだけ。記録は、製品と同じ間隔（2 秒）と判定で再生でき、`crates/core/tests/fixtures/meetings/` に置いた記録は、書いておいた出来事（開始・終了）がその順に起きることを、回帰テストで確かめる。
- **MTG-026** ［単体・結合・E2E］ 会議の検出の記録（MTG-025）は、設定画面の「デバッグ用のログを保存…」で保存する zip（LOG-011）に、`meeting-detection.json` として入れる。形は、`crates/core/tests/fixtures/meetings/` に置く回帰テストの材料と同じ（JSON の `format` が `kiroscribe-meeting-record/1`）。zip に入れるとき（保存とログの提出の両方）は、ウィンドウのタイトルの API キーの形の文字列・URL のクエリ・パスの中の利用者のフォルダの名前を伏せる（LOG-009 と同じ伏せ方。判定に使う末尾が欠けないよう、文字数では切らない）。伏せた記録を再生しても、検出の結果は変わらない。
