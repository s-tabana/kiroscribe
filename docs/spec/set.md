# SET: 設定

設定画面と、保存される設定（API キー以外）。

- **SET-001** ［単体］ 何も保存していないときの設定は、言語「日本語」（ja）、文字起こしのモデル gpt-4o-transcribe、Claude のモデル claude-opus-5-5、マイク「既定のマイク」、相手の声の取り込みオン、自分の呼び名なし、会議の自動検出オン、Windows の起動時の起動オン、新しいバージョンの自動インストールオフ、会議の相棒オン、相棒のモデル claude-haiku-5-5、探すフォルダなし、Kiroscribe の過去のノートオン。本体と画面（プレビュー・テスト用の初期値）で同じ値になる。
- **SET-002** ［単体・E2E］ 設定画面で変えた内容は、「設定を保存」を押したときに保存され、「設定を保存しました」と表示する。保存せずに閉じると、変えた内容は捨てる。
- **SET-003** ［単体］ 保存するとき、言語・モデル・呼び名・マイクの前後の空白を除く。言語とモデルが空なら最初の値に戻し、マイクが空なら「既定のマイク」にする。
- **SET-004** ［単体・E2E］ 保存した設定は、アプリを起動し直しても残る。古い版で保存した設定に新しい項目がなくても読み込め、ない項目は最初の値になる。
- **SET-005** ［結合］ 保存した設定は、次に始める録音、次の議事録の作成・AI チャットから使われる（アプリの再起動は要らない）。すでに始まっている録音には影響しない。
- **SET-006** ［単体・E2E］ マイクの欄には、「既定のマイク（<いまの既定のデバイス名>）」と、使えるマイクの一覧を表示する。保存してあるマイクが見つからないときは「（見つからないデバイス）」として選んだままにする。一覧を取得できなかったときは、欄の下に理由を表示する。
- **SET-007** ［単体］ 言語の欄では、「日本語」「English」「自動判定」から選べる。
- **SET-008** ［単体］ 文字起こしのモデルを選択メニューから選べる（gpt-4o-transcribe〔最初の値〕・gpt-4o-mini-transcribe・whisper-1）。一覧にない値が保存されているときは、その値を選択肢の末尾に出して選んだままにし、保存しても消えない。
- **SET-009** ［単体］ Claude のモデルを選択メニューから選べる（claude-opus-5-5〔最初の値〕・claude-sonnet-5-5・claude-haiku-5-5・claude-fable-5-2）。一覧にない値が保存されているときは、その値を選択肢の末尾に出して選んだままにし、保存しても消えない。
- **SET-010** ［単体］ 設定画面は、Esc、画面の外側のクリック、「閉じる」、× で閉じる。設定画面の上にヘルプを開いているときの Esc は、ヘルプだけを閉じる。
- **SET-011** ［単体・E2E］ 設定画面の「このアプリについて」に、いまのバージョンを「Kiroscribe <バージョン>」の形で表示する。
- **SET-012** ［単体］ 「会議を検出したら自動で録音・文字起こしする」「Windows の起動時に Kiroscribe を起動する」「相手の声（PC から流れる音声）も取り込む」をチェックで切り替えられ、「議事録での自分の呼び名」を入力できる。
- **SET-013** ［単体］ 設定や API キーの状態を読み込めなかったときは、設定画面の下部に理由を表示する。
- **SET-014** ［単体］ 「このアプリについて」の「デバッグ用のログを提出…」を押すと、送るものと送らないものを示し、送信の同意を求める。取り消したら送らない。
  送る zip は「デバッグ用のログを保存…」と同じ内容とする。アプリの動き、会議の検出、アプリと OS のバージョン、秘密でない設定を含む。
  送信時に導入ごとの乱数 ID を添えることと、ID に利用者名や端末名を含めないことを示す。
  録音・ノート・文字起こし・議事録・AI チャットの内容と API キーは送らないことを示す。
  タブの名前には会議でないページやメールの件名も入りうることと、送ったログを 30 日で削除することを示す。
- **SET-015** ［単体・結合］ 確認で OK なら、デバッグ用のログを zip にまとめて、ログの回収の入口に送る。
  確認中から処理が終わるまで、設定を開き直しても提出ボタンは使えない。本体は並行する提出コマンドを断る。
  進捗の購読を登録してからコマンドを呼ぶ。進捗は提出ごとに識別し、処理が終わったら購読を解除する。
  まとめている間は「ログをまとめています…」と表示する。送り始めたら「ログを送っています… <割合>%」と進み具合の棒を出す。
  受け付けられたら「ログを提出しました。提出の番号: <番号>（問い合わせるときに伝えてください）」と「番号をコピー」を出す。
- **SET-016** ［単体］ 送れなかったときは理由を出し、もう一度押せる。
  オフラインのときは、同意画面を開く前に「インターネットにつながっていないため、ログを送れません。接続してから、もう一度お試しください」を出す。
  確認の後にオフラインになっていた場合も、同じ文を出して送らない。
- **SET-017** ［単体・結合］ ログは `<入口>/v1/logs/kiroscribe` に POST で送る。本文は zip のまま（`Content-Type: application/zip`、`Content-Length` 付き）で、ヘッダー `X-Log-App-Version`（アプリの版）・`X-Log-Client-Id`（導入ごとに最初の提出で 1 回作る乱数の ID。利用者名や端末名を入れない）・`X-Log-Token`（提出用の値）を付ける。応答の `id`（英数字とハイフンで 64 文字まで）を提出の番号とし、形が違えば「ログは送りましたが、送り先の応答を読めませんでした」とする。
- **SET-018** ［単体・結合］ zip が 20 MB を超えるときは送らず、上限と「デバッグ用のログを保存…」を案内する。
  恒久的な HTTP エラーでは、アプリの更新とログを保存して別の方法で渡す手順を案内する。
  入口が断ったときは、応答に説明（`message`）があれば 200 文字まで表示する。説明がない場合は、HTTP 413 では上限と保存、HTTP 429 とその他の一時的なエラーでは再試行を案内する。
  つながらない・応答がない（300 秒）・そのほかの通信の失敗は「ログを送れませんでした。<要約>（<原因>）」とする。
- **SET-019** ［単体・結合］ ログの回収の入口と提出用の値は本体に埋め込んだ値だけを使い、設定には持たない（設定画面にも出さない）。古い版で設定に保存した `logIntakeUrl`・`logIntakeToken` は読み込んでも使わず、次に保存するときに消える。入口が使えないとき（E2E テスト用のビルドで入口を指定していないときなど）は、送らずに「ログの送り先がまだ設定されていないため、送れません。「デバッグ用のログを保存…」で保存して、別の方法で渡してください」とする。
- **SET-020** ［手動］ 本物の入口に「デバッグ用のログを提出…」で送ると、提出の番号が出て、入口の置き場所にその番号の zip が置かれる。
